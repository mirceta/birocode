💡→🧩 Ideas that become tasks are consumed

Promoting an idea to a task removes it from the Ideas list and links it to the task. Delete the task and the idea comes back (inactive); complete the task and it stays gone. Play with it below.

        The lifecycle

        1. Promote (Send to graph · Kanban · arch idea_to_task) → the idea is consumed: off the list, linked to the new task. Every path funnels through TaskGraphService.AddNode, so one choke point covers them all.
        2. Consumed, not deleted — kept behind the off-by-default “Consumed” view and list_ideas ... includeConsumed, each showing the task it became.
        3. Delete the task → the idea returns to the list inactive, original text/project/priority intact (only for the idea that task consumed).
        4. Complete/merge the task → a status change, never a delete → the idea stays consumed.
        5. Migration — on first run, ideas that already had a task pointing at them become consumed.

        State lives on the idea as ConsumedByTaskId, so it replicates over the existing ideas sync channel — no new wire shape. openspec ideas-consume-on-promotion.
