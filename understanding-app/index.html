Always-admin status tile

OpenSpec change add-always-admin-status — a header STATUS-strip tile that reports whether this Windows box runs every process with full admin rights (UAC off), and can flip it on with one tap.

Two facts → one state

The whole feature derives from two independent facts the backend reads on every GET /api/always-admin/status. Neither read needs elevation, and neither changes anything.

The edge case that matters: tokenElevated=true with registrySet=false is still disabled — the Operator merely launched the harness elevated under normal UAC. Token elevation only promotes the enabled reading to Active; it never fabricates Active on its own. (Try it: registry off, token on.)

Why the token is the reboot proxy

Writing EnableLUA=0 doesn't take effect until reboot. There's no clean "reboot pending" flag in Windows — but the harness's own token tells the truth: after the reboot, every process of an admin account gets the full token, so the harness reads its own principal and finds Administrator. Before the reboot the account still hands out the filtered token, so the read is false. Registry says "requested"; token says "applied".

This box (as of 2026-07-27) had the values written by a prior agent — so it should read reboot_pending or active depending on whether it restarted since.

POST /api/always-admin/enable — one write, at most one consent

The Enable button's whole contract: write three DWORDs, prompt at most once, never reboot. Pick a scenario and step through.

What Enable deliberately does NOT do

No reboot. Auto-restarting the box from a phone tap is too destructive; the tile shows "restart required" and the Operator reboots when ready.

No Disable button (this change). Rollback = set EnableLUA=1 + reboot — documented on the tile, not automated, so UAC can't be re-armed by an accidental tap. A future change can add it.

No three separate elevations. Batching the writes into one elevated child is why there's one consent instead of three.

Why this feature exists at all

UAC hands even admin accounts a filtered token: every process the harness spawns (Claude Code, git, deploy scripts) starts non-elevated, so admin-needing work either throws a UAC prompt the phone user can't answer or fails silently. The dead-man's-switch rollback already hit this in practice. UAC-off (EnableLUA=0 + reboot) is the machine-wide cure — this tile makes that state visible and settable instead of invisible.

The known cost: with UAC off, Windows Store / packaged apps (e.g. Windows Terminal) may fail to launch. That's why the caveat + rollback (EnableLUA=1 + reboot) are pinned to the tile itself.
