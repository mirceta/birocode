🗒️ advance-queue-loop

Why the queue loop's first real drive (busi-dec, 2026-07-31) died on item 1 — twice — and the four fixes proposed in openspec/changes/advance-queue-loop.

The stash IS the queue

The operator stashes prompts on a dock tab; arming the 🗒️ kind binds the agent's loop slot to that live stash. No snapshot, no cursor — reorder, add, remove while armed.

Any stop is lossless

Unsent items never leave the stash — escalate, cap, error, disarm all keep the remainder. But today, recovery from a stop was entirely manual. That gap is half of this change.

Click an event for the evidence.

1 · Operator stop ≠ agent error

Was: a rescue Stop finalized the run as error, so the loop reported error · the agent's run errored.

Now: runs get a third status stopped; the loop resolves stopped · by-operator. Honest record, remainder kept.

2 · Deny-list that fits honest repos

Was: whole-reply substring — "pushed" hit the term push, so a commit-and-push repo could never pass item 1.

Now: whole-word matching, plus a per-arm trim (drop push/merge for this arm only; global default untouched, disclosed in the gated detail).

3 · One-step Resume

Was: 7 items stranded behind a dead escalate / verify-owed instance; only path back was the full arm form.

Now: a gated Resume re-activates the same instance from the current head — fresh iteration budget, sent-history kept, audit logged. Every activation resets phase, so stale verify-owed never leaks.

4 · The binding is unmistakable

Was: nothing made "this queue drives that repo/tab" conspicuous — the first arm drove the harness itself.

Now: arm surfaces state drives <repo> · tab · N queued and that the head fires when the agent is next free; armed surfaces repeat it.
