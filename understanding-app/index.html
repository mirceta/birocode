👤🧰 my_local_apps — what local apps do I have, where are they, how do I run them

Fleet task f1b0526c · openspec repo-agent-local-apps. One more tool on the repo agents' claude-web MCP server (the PR #126 pattern). It reads the two places the Local tab already reads and joins them by port. Nothing new is stored; nothing is typed in by hand. Click a row below to see the answer the agent gets.

Where a local app is registered (verified in the code)

The repository registryrepositories.json → RepositoryConfig.LocalApps, edited by the Operator's Local setup form. Per app: id, name, port, kind. Kind repo = a product on a loopback port, proxied at /api/localview/<repo>/app/<id>/; kind harness = always-on apps the harness serves itself (Understanding, Goal). No folder, no command.
The discovery cachelocal-app-cache/<repo>.json, written by the Local Apps panel's Discover scan or an imported findings file. Per finding: name, port, folder (repo-relative), evidence, start command, build command. The panel's Run / Stop / Restart resolve everything by port from here. There is no tool.json anywhere — this is what that phrase maps to.
→
my_local_appsjoins the two by port, probes each port live, and answers in words: folder, port, URLs, how to run, how to stop, listening or not. action = list · status · start · stop · restart; app = id, name or port. Start / stop go through the Local Apps panel's own runner and guards (never the harness itself); each lands in the Event Console as "… (agent)".
→
The agent stops hunting the disk"where does the admin console live?" → one call. A registered app that was never discovered says so and names the fix; an app discovery found that nobody registered is listed too, marked unregistered.
