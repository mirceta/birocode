🛰 Fleet Status — a Status panel for every machine

The Management App's Fleet Status now shows each machine's Agents, an Overview (Claude / GitHub / host / admin / version), and a Scoreboard — as tabs, so nothing is crammed. The cheap Overview rides the fleet poll; the heavy Scoreboard loads on demand.

The data path

Overview → in the poll (cheap)

Each peer's /api/arch/peer describe carries an overview: Claude account, GitHub account, host timezone, admin state. Built non-blocking and cached at the source, so GET /api/arch/fleet/status (already polled every 5 s) gains one small object per machine. An older peer sends no overview → the hub shows n/a, never an error.

Scoreboard → on demand (heavy)

The analytics fold re-reads the whole activity.jsonl per call, uncached, and the all window grows unbounded. So it is never in the poll: opening the Scoreboard tab makes one GET /api/arch/fleet/scoreboard?sourceId=&window= (self local, peers relayed & cached ~3 min) with a spinner + Refresh, reusing the harness's own ScoreboardView.

Measured (this machine)

Real ledger 31.8 KB → compute < 1 ms, payload 1.2 KB (today) / 1.8 KB (7d) / 9.6 KB (all). Cheap today, but uncached + unbounded — hence on-demand, so the fleet poll is unchanged. A test enforces the poll payload has no scoreboard field.

Backend: ArchAgentService.PeerDescribe/FleetStatus/FleetScoreboard, FleetOverviewProvider, FleetClient.PeerInfo.Overview. Frontend: manage/FleetStatus.jsx, FleetOverviewPanel.jsx, FleetScoreboardTab.jsx, dashboard/ScoreboardView.jsx. Spec: openspec/changes/fleet-status-panels.
