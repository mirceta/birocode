Brief the driven agent on its situation, every send

Autopilot loops send stored prompt text verbatim, so the driven agent has no idea it is inside a loop. This change prefixes a briefing onto every driven send — a fixed frame around an operator-editable rules list, composed at the engine's one send choke point. The rules live in a global, revisioned store and are edited from a Briefing section beside the loop section on every dock card — so a rule idea is captured the moment it occurs (park it disabled, enable it later), no deploy needed. This app explains why, the composition (D2a/D2b), where it composes, and how the operator surfaces stay honest.

Compose a briefed send — and edit the rules that feed it

Pick what the loop is sending. ComposeBriefedPrompt(kind, phase, sentinel, storedText, rules) renders the fixed frame around your enabled rules, then the stored text. The rules editor below mirrors the dock's Briefing section: check = composed into every driven work send, uncheck = parked idea, every edit bumps the revision each send stamps.     The briefing text is the heart of the change (D2a draft v1 + D2b rules)
    
    
    
      The plumbing is deliberately small; the prompt wording makes or breaks it. Two deliberately
      different compositions — because a verification turn must feel no "act, don't ask"
      pressure — and a deliberate frame/rules split: the parser-coupled marker lines and the verify
      note are compiled in, the behavioral bullets are yours to grow.
    
    

    
    
      
    
        
    Work-phase composition queue item · goal work · recipe
    
        
    
        
    The NEEDS_HUMAN: bullet is part of the fixed frame, not a rule —
        it teaches the exact final-line marker the engine parses, so it can never be edited away.
    
      
    
      
    
        
    Verify-phase note queue step-verify · goal verify · fixed, no rules slot
    
        
    
        
    No posture pressure, no rules, no duplicate marker line — an operator edit
        structurally cannot push "act, don't ask" into a verification turn.
    
      
    
    
    

    
    Crafting constraints that bound future tuning
    
    
    
      
    Short
    The composition should stay around ~120 words. Rule count is operator-controlled now, so the editors show the composed preview with a soft too-long hint instead of hard-limiting.
    
      
    Prefix, not suffix
    Framing lands before the task; the --- The prompt follows. --- separator keeps the operator's text distinct.
    
      
    Exact final-line phrasing
    NEEDS_HUMAN: and the sentinel match the engine's final-line parser — and live in the fixed frame so no edit can teach a marker the parser would miss.
    
      
    One voice with the doc
    The briefing is the distilled form of docs/loop-driven-agent-convention.md; frame tuning edits both in the same commit (D4). Rules tune live in the dock.

    Record raw + a flag + the rules revision; disclose the composition live (D3)
    
    
    
      What was actually sent is briefing + stored, and it must stay reconstructable — even
      though the rules list mutates. But if we stored the composed text verbatim, every truncated surface
      would render the identical briefing prefix as noise. So: record the raw text + a
      briefed flag + the rules revision the send composed with;
      briefing.json keeps every revision, so frame (git) + rules-at-rev (store) + raw text
      (record) reconstruct any past send exactly.
