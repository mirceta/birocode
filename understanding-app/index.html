The fence: why this agent is safe to unleash

Only eight tools

Its --mcp-config lists one server: tasks at POST /api/tasks/mcp. The tool list is list_ideas · create_idea · update_idea · list_tasks · create_task · update_task · link_tasks · delete_task. Nothing reads or writes a repository.

Built-ins disallowed

The run passes the arch agent's --disallowedTools list (Edit, Write, Bash, Read, Glob, Grep, WebFetch, …) and its home folder's .claude/settings.json denies Read under every registered repo and the data dir.

Bearer token, not the password

The MCP route is exempt from the password middleware. Instead the harness mints a 256-bit token per process, writes it into the run's MCP config, and compares it in constant time. Wrong token → 401, no tool runs.

Everything audited

Every tool call writes one row to the autopilot action audit (kind tasks, outcome tasks-tool, phase = tool name). The Tools lane counts them per tool.

Cycles cannot happen

link_tasks is a thin wrapper over TaskGraphService.AddEdge, which refuses missing nodes, self-loops, duplicates and cycles. The refusal comes back as an isError tool result with the reason, so the model fixes its order instead of retrying.

No second store

The tools call the same NotesService and TaskGraphService the Ideas tab uses. Agent-created entries sync, merge and tombstone exactly like typed ones.

What lands on the graph

The fixture prompt from the goal, as the agent typically splits it. Arrows read "depends on". Nodes are auto-placed in rows of four (the second row starts when the first holds four).
