Why this works (the research finding, 4/4 against real Edge/Chromium)

  • Named target reuse: window.open(url, name) with a non-_blank name REUSES the window this page opened under that name and navigates it — it never opens a second one. Verified: .claudeweb-preview/playwright/check-worker-window.mjs.
  • Cross-origin is fine: the opener may always navigate a window it opened (192.168.0.101 → 192.168.0.104 → self); it just can't script its content — which nothing here needs.
  • Survives reload: after M reloads, the association holds — the same W is re-adopted (measured, not assumed).
  • The instinct was half right: an unrelated tab can't be retargeted (global name matching was removed from browsers). A window M itself opened can — that's the loophole this feature stands on. So: pure web, no WinForms app needed (the two-WebView2-forms fallback is documented in the openspec design, unbuilt).
  • Deep link: the URL ends /studio?agent=<repoId> — the dock resolves it on load (id → handle → name), opens/activates that agent's tab, then strips the param.
