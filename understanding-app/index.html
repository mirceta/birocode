Discover Apps Panel

openspec change discover-apps-panel — the dock slims to two buttons, a panel overlay hosts the findings, the cache becomes a union, and records get an explicit delete.

The two problems

UI sprawl The dock's discover section had grown into a full findings list with per-row Run / Check / Register, a Load-cache button and status messages — eating the phone on repos with many apps.

Data loss LocalAppDiscoveryCache.Save overwrote the cache on every successful scan. The discovery agent routinely finds only a subset per run, so a later partial scan silently erased apps an earlier scan had found.

The four fixes

FixHow
Two-button dockThe strip keeps only 🛰️ Discover (runs the scan, shows the spinner) and 📋 Local apps (opens the panel). Nothing else renders inline.
Panel overlayDiscoverAppsPanel.jsx renders inside the dock (the .phone is position:relative), hosting findings + all per-row actions + cache/job state. Same hook state as the dock buttons — one poll, one snapshot.
Union cacheSave merges by port: new scan wins its ports, cached ports the scan missed are kept. Each finding carries its own discoveredAt; the merged set becomes the in-memory job result too, so Run-by-port works for every cached app.
Explicit deleteDELETE /api/local-apps/cache/{port} — the only removal path now (a rescan never drops records). Edits the disk cache and the in-memory job; deleting the last record leaves cached-empty, distinct from no-cache.

BREAKING semantics Before: an app that disappeared from the repo vanished from the cache on the next scan. Now it persists until you delete it — that implicit drop was exactly the data loss being fixed. The per-row age makes stale records visible; the 🗑 removes them.

A working miniature of the real dock. Click 📋 Local apps to open the panel; delete rows with 🗑 (state resets on reload).
