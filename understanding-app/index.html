What a preset is

    
{ id, name: "Status | Kanban | Subagents", auto: true,
  panes: [{ tab: "status" }, { tab: "kanban" }, { tab: "subagents", sel: "<conversation>" }],
  fractions: [0.153, 0.264, 0.583],          // sum 1 → survives window resizes
  created, updated }

    
Which existing state it maps onto

    

      
ManageApp keyapplied as

      
manageapp.layoutpanes if 2+ panes, else tabs

      
manageapp.paneOrderpreset panes first, the rest keep their relative order

      
manageapp.hiddenevery tab not in the preset

      
manageapp.paneWeightsfraction × pane count for the preset's panes

      
manageapp.tabthe first pane

    

    
Nothing is written until a preset is applied: loading the page and saving presets leave the Operator's view untouched (lab check 1b). A tab that no longer exists is skipped with a toast; the rest share its width.

  





  

    
Two copies, browser wins

    
browser localStorage  manageapp.viewPresets   ← the working copy
hub                   GET/PUT /api/settings/view-presets  (view-presets.json)

on load   browser empty, hub has some  → adopt the hub's
          hub empty, browser has some  → push the browser's
          both, different              → keep the browser's, show ⇅ Sync
on edit   browser first; the hub follows if the two agreed before
⇅ Sync    union by id, the browser's copy wins a conflict → written to both

    
Why Alt and not Ctrl: Chrome/Edge reserve Ctrl+1..9 for switching browser tabs. A page can't claim it.
