Pull (every PollSeconds, default 30)

  1. GET ?fn=get → {ok, rev, store} (served via the Apps Script 302-redirect shape; the client just follows it)
  2. If rev moved since last seen → MergeFrom(store): union by note Id, newest UpdatedAt wins, tombstones suppress/revive
  3. If the merge finds local content the remote lacks (e.g. edits made offline) → mark dirty, push soon

Push (debounced ~2s after any local add/edit/delete)

  1. Pull + merge first — a push always uploads the merged board
  2. POST {baseRev, store} — the script accepts only if baseRev equals its current rev, then bumps rev
  3. On {conflict:true} (someone wrote in between): re-merge against the returned store, retry — up to 3 attempts
  4. On failure (offline, error): stay dirty; the retry rides the poll cadence until it lands

One-time, by the operator (~3 minutes)

  1. Open script.google.com → New project, paste the contents of docs/ideas-sync-appscript.gs
  2. Deploy → New deployment → type Web app → execute as Me, access Anyone → copy the …/exec URL
  3. On each harness: Ideas tab → ☁ Set up sync → paste the URL, tick Sync on, Save
  • To update the script later, edit the existing deployment (Deploy → Manage deployments → ✏) — a NEW deployment gets a new URL and every harness would need re-pasting.
  • The store is claude-web-ideas.json in the operator's Drive, created empty on first use — inspectable and restorable by hand.
  • Config lives per-box in %APPDATA%\ClaudeWeb\ideas-sync.json; the endpoints are GET/PUT /api/notes/sync/config and GET /api/notes/sync/status.
