Yes — it's "just another toolset". But it's tools, not a skill.

A skill

Instructions loaded into the agent's context. It changes how the agent works, not what it can touch. No new powers.

Browser mode (this feature)

An MCP toolset (mcp__claude-in-chrome__*) injected into the session because the harness added --chrome to the spawn. The agent gets genuinely new abilities: open tabs, read pages, click, type — in your real profile.

How you'd use it

Exactly like you guessed: you tell it explicitly. Toggle browser mode on for the session, then say what you want in plain language — "check my Gmail", "open the CRM and pull the open deals". No selectors, no scripts: the agent finds "the search box" semantically.

The key property: it is your Chrome profile — cookies, SSO, MFA, password manager already live. Gmail doesn't see a bot logging in; it sees your existing session opening a tab. That's why "check my emails" just works with zero setup.
Same agent, both hands: one session can edit repo code and drive the browser — build a change, open localhost, read the console, fix, re-verify. It's not a separate "browser agent"; it's your normal chat session with one more toolset.

The three catches to keep in mind

1

It acts as you

Anything your logged-in self can do, the agent can do — including sending mail, not just reading it. That's why the proposal makes browser mode per-session opt-in behind the auth gates, never a default, and never available in the read-only "ask" lane.

2

One browser session at a time

The extension's native-messaging pipe has a single holder. Two chat sessions both in browser mode would collide — so the harness serializes them: one runs, the other waits or is refused with a clear message.

3

You're on the phone; the browser is at home

Login walls and CAPTCHAs normally pause for "the human at the browser" — but that human is you, away from the PC. Your existing sessions usually mean no login is needed, but when one is, the run can stall until someone is at the host. The status surface will say so instead of hanging silently. Also: the agent's tabs live in a visibly colored tab group; drag a tab into it to hand the agent a page, drag it out to take it away.

Still open (design phase): our harness spawns a fresh claude -p --resume per message. Whether the resumed run re-attaches to the same tab group or opens a new window every turn is the load-bearing unknown to verify first.
