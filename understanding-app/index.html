Rules that make it predictable

  

    
Fixed grid
Occurrences are anchor + k·every. A run that starts late or loops for 40 minutes never shifts the next one. Creating a card does not fire it — Run now exists for that.

    
One pending occurrence
Harness off overnight, gate closed, the slot busy for three hours: the card runs once, for the newest occurrence, and the run says "covers 4 earlier occurrences". Never a burst of replays.

    
The loop slot is the arbiter
An agent has one loop slot. A due card waits in the scheduler while a turn runs or any other loop holds the slot; nothing is stashed in the agent, nothing is pre-empted, and the slot is handed back as it was found.

  






  
What already exists — and what it is used for

  

  
Why not just…

  

    
…a fifth loop kind (cron)?
The loop kinds describe how a run behaves, and the goal kind is exactly right. What is missing is the clock and the card: many schedules per agent, a history per schedule. There is one loop slot per agent, structurally, and no loop record has an interval. So the schedule lives outside and arms the goal loop — no new kind, no change to the engine.

    
…a Kanban card with a repeat field?
Board cards get delivered: todo → … → pr-merged, verified against git and GitHub, read by the policeman, judged stuck or dishonest. A recurring task never delivers, so every one of those rules would need an exemption. Same look, separate entity — with an optional bridge: a run that ends ATTENTION can create a board card.

  






  
Two files in the data dir

  

    
recurring.json — the cards

    
recurring-runs.jsonl — one line per occurrence
Append-only; a later line with the same id replaces the earlier (running → done). Compacted at startup, 500 kept per card. The per-turn trail of a run is the existing autopilot audit.

  

  
The goal the loop is armed with

  

  
The goal loop's own templates wrap this text into the work prompt ("Work toward this goal until it is genuinely achieved… end with LOOP_DONE") and the verify prompt ("Critically verify it against the ACTUAL state of the repository… end with GOAL_VERIFIED"). The result line sits above GOAL_VERIFIED and is read deterministically — no model, no arch relay.
