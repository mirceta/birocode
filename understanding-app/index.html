Repo sounds & cue latency

openspec change repo-sounds-and-latency — why cues took 5–10s (or never came), what changed, and how a cue is now picked per repository.

1 · Why the sound was late — and the fix

click dock chat→ POST /api/events/chat-focus→ HarnessEventFeed.Publish→ collector ingest→ 🔊 host cue

The cue only fires at collector ingest. Before: one sequential poll pass every 2.5s, and the dead "monster" source burned its full 6s HTTP timeout before the in-process self source was even read. After: publishing triggers self ingest immediately, and remote sources poll in parallel — a dead remote delays only itself.

Before
0s2s4s6s8s10s
After
0s2s4s6s8s10s

Also fixed for "sometimes no sound at all": the composer's chat-focus damping dropped from one event per 10s to per 3s, and because events no longer arrive in one late batch, the host's 400ms debounce rarely swallows them anymore. (Measured on an isolated instance with a dead source registered: publish → ingest in ≈0.7s, vs ≈5–10s before.)

2 · Which sound plays? (host and device use the same precedence)

Set up which rules exist, then pick the incoming event — the winning layer lights up.

The one asymmetry, on purpose: a repo _default covers every event from that repo (that's the "give this repo its own voice" feature), while the global _default keeps its old meaning — unknown types only. Device cues in the events-app resolve the same way, with the browser synth as the built-in layer.

3 · Where things live

host rules→server-side files under collector-host-cues/ (global) and collector-host-cues/repos/<key>/ (per repo, with a .repo sidecar naming it)
device rules→browser IndexedDB; repo-scoped records use a composite repo␀type key, old plain-type records stay the global layer
API→/api/collector/sound/rules/<slot>?repo=R — omit ?repo= and everything behaves exactly as before this change
