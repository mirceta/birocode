👮 The Kanban policeman — how the board stays honest

openspec kanban-board-integrity · fleet task b2ea0809 · four pieces, one verifier, one "needs human" state

Every minute, the same pass — now with a second step

The harness already had the only thing that knows the truth about a card: the verifier (assignee's clone → git facts, GitHub → PR facts, deploy log → "live"). The policeman is not a new prompter or a new loop. It is the second step of that pass: it reads the facts the first step just recorded and judges each card.

What the policeman says about a card

Pick a card. The verdict is a pure function of the card's facts (BoardIntegrity.Judge, unit-tested).

manualnode.manual — not judged at all
dishonestcolumn ahead of the verified facts — the SAME rule as the ⚠ unverified badge (TaskLifecycle.IsUnverified); reason = that badge's text
stuckpinged · no PR · and either the note says TASK BLOCKED (the arch's relay) or silent past the board's stale window in doing/committed
honesteverything else — including delivered cards and never-pinged ones

One "human assistance requested" state — three raisers, one resolver

A card carries at most one needsHuman { at, by, reason, requestId? }. Whoever raised it, the Operator sees the same 🆘 badge, the same needs human filter flag, and the arch sees the same needsHuman in list_tasks.

👮
policeman

stamps a stuck card; withdraws only its own stamp when the card progresses (a PR, delivery, going manual)

🤖
agent

request_human (openspec human-delegation-watchers, in flight) sets by: "agent" + the request card's id; the watcher's resolution clears it

🧑
operator

"🆘 Needs human" on the card; "✓ Resolved" clears it whoever raised it

This is how the two changes compose without a second scheme: the watchers change owns the request card and the resume; this change owns the state on the work card and its badge. Neither touches the other's stamps.

✋ Go manual — the harness lets go of the card

The Operator drives that repo agent directly on its machine, not through the arch. So every automatic hand backs off:

  • 🔎 verifier — no probe, no auto-advance, no ⚠ badge
  • 👮 policeman — not judged, not stamped (going manual drops the policeman's own 🆘)
  • 🏛 arch — never awaitingDispatch; dispatch_task and update_task answer manual
  • 📣 the board's own Ping — disabled

Flip it back with "↩ Back to auto": the next pass judges the card again.

🎯 The board goal — the reference

The Operator writes what the board is for. It lives on the fleet-synced board (last writer wins, like the scratchpad; an older peer cannot erase it). Two readers:

👮
policeman

mechanical: shows its verdict beside the goal so the two are read together — "checked 12 s ago · 5 honest · 1 dishonest · 1 need human · 1 manual"

🏛
arch

judgement: reads boardGoal in list_tasks on every wake and says when the board's state does not make sense for it

A timed LLM "goal check" is a natural watcher condition later — listed as a follow-up, not forked now.

💬 Provenance and control: the policeman is an arch conversation

The mechanical judge (previous tabs) is silent. For provenance (what is it doing, what has it done) and control (stop it, ask it something) the policeman is also an arch conversation — @arch:policeman — living as a subtab of the Kanban. Nothing is reinvented:

🔁
the loop

the engine's recipe loop, one fixed prompt ("is the Kanban honest?") re-sent every interval; a tick re-arms it when capped or errored, never over your Stop or a pending question

🔌
the tools

the arch's MCP server, with an observe-only policy for this conversation: list / read / git_state / recall plus board_integrity, flag_needs_human, clear_needs_human; every mutating tool is refused in-band

🧾
the history

the arch's chat, tool-call history and loops lane — the same page as the Arch tab, pointed at this conversation

The context cap

A forever loop grows its session without bound. After every turn the harness reads the CLI's reported context; at the cap (400k by default) it rolls over: closes the session in the sessions strip with the reason, starts the next prompt in a fresh CLI session, and prefixes it with a mechanical handover — which session ended and why, the board's verdict now, every card carrying a request. Nothing is lost: the policeman's state is the board. Old sessions stay listed; click one to read its tool calls.
