The stash IS the queue — verified by default

The third promised autopilot mode is a wire between two things that already exist: the per-tab prompt stash (the ideas you flag while the agent is busy) and the loop engine. Arming a 🗒️ queue loop means: automatically unload my stash into the agent whenever it's free — and, by default, verify each step actually got solved before unloading the next.

≡ The design in six properties

Decided in openspec/changes/queue-based-loop — the live-stash model merged with the loop engine's existing machinery. Implemented: QueueLoop.cs + engine consume-on-land, the dock control's Queue type, and the console's Loops → Queue tab.

🛡 Why this stays honest and safe

🔎 Honesty without a frozen copy

Every auto-sent byte is a stash item you can already see above the composer; verification prompts are a stored template (gated-inspectable) + that visible step text, composed deterministically at send time. The audit trail still records every actual send verbatim.

visible stash item ≡ → auto-sent chat message

🪜 Four ways it stops before making things worse

As a driven QueueLoop kind it inherits the ladder, plus the new verification gate — and because unsent items never leave the stash, every stop is lossless:

  • errored runthe last turn failed → stop, don't pile on
  • NEEDS_HUMAN:the agent used the sentinel → escalate
  • deny-listthe load-bearing fence → never auto-send past it
  • step-unverifiedno STEP_VERIFIED → escalate — catches plain questions the ladder can't, because ordinary agents don't know any sentinel

⌘ Three surfaces, one list

The stash strip stays the queue's only editor — the loop surfaces add settings and arming, never a duplicate list.
