LAN bypass for the IP gate openspec lan-bypass-ip-gate

What the gate decides now, why the socket peer is never the input, and why it fails closed behind a forgetful proxy.

The tax. The IP gate admits exact IPs only. Every harness in the fleet (this box, MONSTER at 192.168.0.143, any future peer) talks to the others from a LAN address, so each pair needed both IPs approved by hand on both sides, and a missed one showed up as a silent 403. Same for the Operator's own phone/laptop on Wi-Fi every time DHCP moved it.

What the gate really buys. It hides the login page from the internet. Everything that passes it still needs the password, and a compromise behind the password is total (the harness runs claude with --dangerously-skip-permissions as Administrator). So keep the gate for the internet door, and stop applying it to addresses that are physically on the Operator's own network.

The change. A host-side list LanBypassCidrs (e.g. 192.168.0.0/24). A request whose resolved client IP falls in a range skips the guest list. Default is empty, so nothing changes until the Operator writes a range down. The web UI can only show it, never edit it (the old asymmetry rule stands).

Convention changed on purpose. plans/auth-ip-filter.md said "exact IPs only, no CIDR, no exemptions". The Operator was warned and confirmed on 2026-09-03.
