Dock toolbar dot: the ! unseen-result latch

My understanding of what you asked for — the problem, the fix, every state the (agent × dashboard) pair can be in, and the questions I'd want answered before proposing it.

The information-loss hole (today's behavior)

You hide an agent's dock from the grid while it is executing. The strip dot correctly goes black. Then the agent finishes — and the dot reverts to the agent's color, which reads as idle. The fact that you were waiting on that agent is gone: nothing tells you there is a finished turn you haven't looked at, so there's no urgency to re-show the dock.

The fix you're asking for

When a run finishes while the dock is hidden, the dot does not go back to the agent's color — it turns into an exclamation point: “this agent finished and you haven't seen the result.” It stays an exclamation until you show the dock again (click the tab), at which point it returns to the agent's color, because now the grid card itself carries the result.

Key reading: the exclamation is an acknowledgement latch, not a status. Running / idle / error describe the agent; the exclamation describes you — “you have not looked yet.” It can only exist on a hidden dock; showing the dock is the act of looking, which clears it.

    Questions before I propose it

    1. Error while hidden — same exclamation? A hidden run can finish in error, not just done. I'd show the exclamation in both cases (both are “unseen outcomes”), but style it red for error vs near-black for done, so the strip also tells you what kind of result awaits. OK, or one uniform exclamation?
    2. What counts as “showing”? I'd clear the latch whenever the dock becomes visible on the dashboard grid — whether via the strip tab, or the ▦ toggle on the Agents page. Not clear it on merely opening the chat elsewhere. Agree?
    3. Should the latch survive a page reload / phone re-visit? If we detect only the running→finished transition in the browser, a finish that happens while nobody has the dashboard open (very much your use case — you're away) or a reload afterwards would lose the exclamation. To be robust I'd persist it server-side on the dock (a small “unseen result” flag set when a run ends, cleared when the dock is shown), rather than frontend-only. This is the main reason the feature is “more complicated,” as you suspected.
    4. Clicking the exclamation tab keeps the normal toggle behavior (it shows the dock, which clears the latch) — no separate “dismiss without looking” affordance. Right?
    5. Docks that are shown but scrolled out of view still count as “shown” (case 3, no exclamation) — visibility means “on the grid,” not “within the viewport.” Confirm?
