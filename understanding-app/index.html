Dock App Split View

openspec changes dock-app-split-view + split-divider-drag + split-no-forced-wide — a per-dock mode that puts the opened local app beside the chat instead of over it, with a draggable divider between the two panes. Split stays inside the dock's normal footprint; widening is always the manual ⤢ choice.

The problem

Cover only Clicking a local app in a dock rendered it over the whole dock: the chat collapsed to a composer-only strip and the git/discover chrome hid. Fine for a quick look — useless when you want to watch the app while talking to the agent about it.

The change

PieceBehavior
Split modeA ◫ toggle appears in the dock's app-switcher row while an app is open. On: the dock's chrome stays in place, and the screen area splits — full chat (message list + composer) left, the app right. Off: cover, exactly as before.
Chrome returnsIn split the dock is treated as "chat showing": git block, Discover buttons, Understanding row all come back (they hide only in cover).
No forced widening(openspec split-no-forced-wide) Split originally forced the dock's grid cell to span 2 columns — the same "expanded" state as the ⤢ toggle. That coupling is now removed: split renders inside whatever cell width the dock already has, and widening is always your explicit ⤢ choice (which works independently, before/during/after split). Pane floors adapt on narrow cells (min(300px, 45%) chat / min(260px, 38%) app) so the panes always fit, and the chat clips at the divider instead of bleeding under the app.
Draggable dividerThe line between the panes is a real separator: drag it (mouse or touch) to give the app or the chat more room. Clamped so neither pane collapses (chat ≥ 300px, app ≥ 260px); double-click resets to 50/50; arrow keys nudge it when focused. The drag keeps tracking even over the app's iframe.
EphemeralPer-dock, device-local, resets on reload — the same class of state as maximize-chat; the drag ratio follows the same rule (it survives split off/on while the dock is mounted). Advanced-mode toggle (dockAppSplit); Basic keeps cover.

Guarantees kept Toggling cover ↔ split never reloads the app (same keep-alive frameKey, so in-app state and per-frame zoom survive) and never remounts the chat (composer draft, scroll, live stream survive). Verified headlessly: 32/32 + 18/18 checks.

A working miniature. Click StateA to open the app (cover), then the ◫ toggle — the chat comes back beside the app inside the dock's own footprint (the dock does not widen; the neighbor stays put). Then drag the divider between the panes (double-click it to reset) — the fake in-app counter proves resizing reloads nothing.

What to notice

• The ◫ toggle only exists while an app is open — it changes how the app shows, not which app.

• Cover hides the git row and collapses the chat to its composer; split brings both back.

• Split does NOT change the dock's size in the grid — the panes share whatever width the dock has. (It used to force the ⤢ two-column span; that's gone.)

• The app pane is the same iframe in both modes — the mock fakes it, the real dock moves a slot the keep-alive host tracks.

• The divider drags between the panes' minimum widths, resets on double-click, and its ratio sticks per dock until reload.

Why toggling loses nothing

Two prior contracts do the heavy lifting; split just leans on them:

Chat is always mounted in .phone__main, last child, both modes→ toggling split only adds/removes the sibling .phone__side→ React never remounts the chat (keep-composer contract)
iframe lives in the root LocalAppFrameHost, not the pane→ both panes render a slot with the same frameKey dock:<dock>:<repo>:<app>→ host re-tracks geometry; the iframe is never re-parented → no reload (state-preserve contract)

The alternative — actually moving the <iframe> between panes — would reload the app on every toggle: re-parenting an iframe resets its document. That's the whole reason the keep-alive host exists.

Headless proof (32/32 + 18/18)

The split check seeds three kinds of state before toggling: an in-app counter + input (inside the iframe), a composer draft (chat subtree), and per-frame zoom (host). It then asserts all three survive cover → split → cover, that exactly one app iframe ever exists, that the grid cell keeps its width (and manual ⤢ works independently of split), and that the panes fit a normal-width cell with no horizontal overflow. .preview-test/split-view-check.mjs. The divider check drags across the iframe, asserts live pane resize with no reload, both clamps, double-click reset, keyboard nudge, and that the ratio survives split off/on. .preview-test/split-drag-check.mjs.
