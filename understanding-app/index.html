Each box is one hop of the configuration (left half) or of a live tool call (right half).

The sibling platform repo once committed a live API key inside a repo-level .mcp.json. This design makes that mistake structurally impossible here:

✓ The path the key takes

  1. Typed once into the Tools lane masked input
  2. PUT /api/tools/birokrat — the only hop carrying the full key
  3. Stored in %APPDATA%\ClaudeWeb\tools.json host-side
  4. Per run: temp mcp-<guid>.json under app-data deleted in finally
  5. Read-backs return only apiKeySet + last-4 hint masked

✗ Paths the key never takes

  1. The repo working tree — no .mcp.json is ever written there committable
  2. GET responses — a stored key never travels back to a browser
  3. Harness logs — only "MCP tools config injected" is logged
  4. Files that outlive the run — stop, crash, or success all delete the temp config
Untouched masked field on save = apiKey: null = keep the stored key. The explicit ✕ button sends "" = clear. Same per-entry contract inside the company list.

The MCP server reads everything from env vars. The harness assembles them exactly like the proven reference integration (api-chatbot's server.js):


    

      
Env varMeaning

      
BIROKRAT_API_KEYDefault company's API key (a Birokrat "company" IS a key + URL pair)

      
BIROKRAT_API_URLBase URL, default https://next.birokrat.si/api/v2/

      
BIROKRAT_API_KEYSJSON map name → {apiKey, url?}. When present, every generated tool gains an optional company enum param; the first entry doubles as the default

GotchaWhy it matters

      
~300 deferred toolsClaude Code defers the schemas; the agent loads them via ToolSearch. Our lanes don't restrict tools, so this works — but any future allowed-tools tightening must keep ToolSearch. verified live: keyless server start → tools listed → schema loaded

      
Enabling arms BOTH lanesAsk runs in plan mode, which blocks harness-side writes — but MCP tools execute server-side and Birokrat has mutating endpoints. The per-repo enable toggle is the explicit opt-in; the panel copy says so.

      
Missing server scriptEnabled + missing dist/index.js → the panel shows an explicit error naming the path, and BuildMcpConfigJson independently refuses, so runs launch clean rather than with a broken MCP server.

      
Slow tool calls are normalBirokrat answers HTTP 202 while processing (client polls 3s × 10) and rejects concurrent requests per key. A minute-long tool call is expected, not a hang.

      
Errors look like successesNon-OK HTTP comes back as normal tool-result data {error:true, statusCode…}, not an MCP tool_error — read the payload, not just the frame.

      
Keyless start succeedsThe server boots with a stderr warning and registers all tools; calls fail at execution time. "Tools visible" ≠ "key configured".
