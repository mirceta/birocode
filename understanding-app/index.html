loop-eval — one suite, two run modes

openspec: add-loop-eval-live-mode · the same real-agent scenarios, runnable as an automatic gate (isolated) or where you can watch them (live)

Why two modes?

The suite proves the one thing no cheap test can: the loop engine drives a real agent to a real goal. That proof serves two different customers:

  • An agent needs it fully automatic — boot, run, assert, tear down, exit code. That's the isolated mode (default): a throwaway harness on :5210 that no human ever sees.
  • The human operator needs to see it with their own eyes — a repo card appearing, the agent dock filling with real turns, the Autopilot console's loop card ticking work → verify → done. That's the live mode (--live): the same scenarios pointed at the running :5099 harness.

Same scenario files, same assertions, same deadlines — only the world differs. The mode split lives entirely in tests/loop-eval/lib.mjs.

Isolated for agents

node tests/loop-eval/goal.mjs

Boots its own ClaudeWeb copy on :5210, seeds gate + kill switch into a scratch datadir before boot, runs, kills everything. Live harness never touched.

Live for you

LOOPEVAL_LIVE_PW=… node tests/loop-eval/goal.mjs --live

Targets the harness you're using right now. Registers loopeval-goal-live, prints a watch banner, runs where you can see it, cleans up after itself (LOOPEVAL_KEEP=1 to keep the aftermath).

Shared core — identical in both modes

The autopilot gate is host-only. Both modes respect that — differently.

There is no enable endpoint, ever (AutopilotGate.cs). So how does a test suite arm loops at all?

IsolatedLive
Gate + kill switch Writes autopilot-gate.json + autopilot.json into the scratch datadir before boot — a host-side file write, the same trust level as the operator clicking the host GUI. Checks, never sets. gateOpen off /api/autopilot/loops, killSwitchEnabled off the debug bundle. Off → fail fast with the exact thing to click.
Password Invents a throwaway one for its own instance. LOOPEVAL_LIVE_PW — you hand it over explicitly. Never defaulted, never read from the live secret store.
Loop internals for asserts Reads scratch loops.json / autopilot-audit.jsonl directly. Reads GET /api/autopilot/loops/{repoId}/debug — the shipped debug bundle. The live datadir is never written and never parsed.
Residue Whole scratch root deleted; instance killed. Stops loop → closes dock tab → unregisters repo (registry entry only) → removes scratch copy. Next run's preflight catches any leak (loopeval-*-live name check).
