openspec human-delegation-watchers · proposal, 15 September 2026

Let an agent hand a blocker to a human,
and come back by itself when it's done.

Two ideas arrived together. One is a new kind of loop; the other is the first thing worth building with it. This app separates them, walks the flow, maps each piece onto what the harness already has, and collects your answers to the open decisions.

A prompter pushes prompts on a timer. A watcher checks a condition and reacts.

What exists · prompters

Every loop today decides the agent's next prompt

  • 💡 Suggestion — classifies the trailing reply, proposes the next routine
  • 📋 Recipe / Queue — unloads a scripted list one prompt per turn
  • 🎯 Goal — drives toward a goal, verifies steps
  • 🏛 Arch ladder — the management agent on a timer, polling passive repo agents

Shared mechanics in the engine: idle detection, dedup, cap, kill switch, audit. The kind only answers "what next?".

What is new · watchers

A watcher decides nothing until a condition becomes true

  • Ticks with the same engine, same kill switch, same audit
  • Its decision is hold every tick… until the condition fires
  • Then it runs one reaction (a hook) and retires
  • First condition: a human request was resolved. First reaction: resume the agent

Same ILoop seam, opposite shape. Later conditions (a PR merged, a URL healthy, a file changed) are new condition kinds, not new machinery.

The gap this closes. Today a blocked agent can only end with NEEDS_HUMAN: <question>. The engine treats that as a hold: the loop parks and the question is shown on the dashboard. Nothing tracks whether the human acted, nothing tells the agent, and the agent never resumes by itself. NEEDS_HUMAN: stays as the fallback for agents without tools.
