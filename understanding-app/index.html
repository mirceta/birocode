Two paths, one result shape

Discover local apps — runs the read-only agent scan of the repo, returns the typed list, and now write-throughs that result to a per-repo JSON file on disk. The scan itself never touches the scanned repo; the write is a separate harness-side artifact in the harness data dir.

Load cache — reads that JSON straight back and returns the same shape as a live scan (name, port, folder, evidence, startCommand), so the register / Run / Check rows work identically. No agent runs. Each app's running dot is still recomputed live from a port check at load time — never frozen into the cache.

  • Restart-proof: the old registry was in-memory latest-only — a restart dropped it. The cache survives on disk.
  • Rediscover stays one click away: added a new app? Hit Discover; a fresh scan overwrites the cache.
  • Best-effort write: a cache-write failure is logged and swallowed — discovery still returns its result.
  • No cache yet returns an explicit status:"no-cache" so the dock says "run Discover first" rather than showing an empty list.
