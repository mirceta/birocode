Live, real data — and where the line was

  • The live process was measured directly: tools/livetrace for every request under real traffic, dotnet-stack for what the slow requests were blocked on, and the hub's own log since the deploy. No fixture involved.
  • The browser waterfall needs a logged-in browser. An agent holds no login for the hub (sessions and the password are stored hashed) and must not forge one, so the waterfall ran against the same build over a same-minute copy of the live store, with all six real peers polled read-only — the same cards, docks, repos and fleet.
  • The LAN rows are a model (Chromium throttled to 25 Mbit/s, 10 ms): they show how bytes turn into seconds for a browser that is not on the hub itself.
  • To confirm on the hub after a deploy: run the same tracer and compare the same rows.
