The loop briefing — telling the agent it's in an autopilot loop

An autopilot loop resends stored text to Claude with no framing, so the agent behaves as if a live human just typed it — it asks, plans, hedges. The loop-agent-briefing change prepends a short situational briefing at the one send choke point. The plumbing is tiny; the briefing wording is the whole deliverable — promoted to design section D2a so it gets reviewed, not improvised.

openspec: loop-agent-briefing D2a — draft v1 work core ≠ verify note

1 Why framing at all — the same prompt, two readings

A terse queue item like Add a --dry-run flag to swap.ps1 reads one way to a human at a keyboard and another way to an agent that doesn't know nobody is watching. Nothing in the stored text tells it which world it's in.

▁ raw send — no briefing

Agent assumes a human is reading in real time.

Happy to add that. A couple of questions first: should -DryRun also skip the health-check, or just the file swap? And do you want it on by default in CI? Let me know and I'll implement.
✗Goes nowhere. No human answers; the loop stalls or the next tick re-asks.

▔ briefed send

Agent knows: automated loop, no live reader, act now.

Adding -DryRun to swap.ps1. Chosen defaults (stated): it previews build + guard and never touches live, and stays off in CI. Implemented, guard preserved, dry-run verified. …
✓Does the work, picks sensible defaults, and says which — exactly the posture the briefing asks for.

2 One choke point brews every send

D1: compose the briefing where all sends already funnel — AutopilotService.SendPrompt — not inside each loop kind. Five send shapes, one wrapper, zero per-kind drift. Suggest mode branches off earlier, so a human-composed prompt is never briefed. Click a shape to load it into the builder below.

▸
ComposeBriefedPrompt(kind, phase, sentinel, storedText)
Returns briefing + "\n\n" + storedText. propose.Prompt stays the raw stored text everywhere the engine records or quotes it (D1) — only the actual CLI send is wrapped.
✕ Suggest mode returns before this path — its pending prompt is human-sent from the composer, so a human really is in the loop. Never briefed.

4 Why work and verify get different text

The tempting shortcut is one briefing for every send. But "act, don't ask; choose defaults" is exactly the wrong pressure on a turn whose whole job is to judge honestly. So D2a splits the text.

if verify got the work core…

verify prompt
Did the agent add the -DryRun flag? Confirm.
↓  “act, don't ask · choose a default”
agent
Defaulting to done. STEP_VERIFIED
↓
result
False confirmation silently corrupts the run.

the verify note it actually gets

verify prompt
Did the agent add the -DryRun flag? Confirm.
↓  “judge honestly · refusal only stops the loop”
agent
Flag is absent from swap.ps1. Not verified.
↓
result
Honest refusal stops the loop for a human — cheap, recoverable.

This asymmetry is deliberate: a wrong STEP_VERIFIED is expensive and invisible; a wrong "not yet" is cheap and loud. The verify note optimizes for the cheap failure.

5 Four constraints that bound future tuning

The draft ships as v1 and gets tuned from real runs — but only within these rails, so tuning can't quietly break the contract the engine and the convention doc rely on.

✂ Short — under ~120 words

The core frames the stored prompt without diluting it. It's a fixed per-send token cost, so it stays lean. (See the live meter in §3.)

⬒ Prefix, not suffix

Framing must land before the task. The --- The prompt follows. --- separator keeps the operator's text visually and semantically distinct from the harness's.

⌁ Exact final-line phrasing

NEEDS_HUMAN: and the sentinel must match the final-line format the engine's parser already anchors on — the briefing must never teach a marker the parser would miss.

≡ One voice with the doc

The briefing is the distilled form of docs/loop-driven-agent-convention.md. Any edit changes both in the same commit (D4) — no drift between what's told and what's documented.
