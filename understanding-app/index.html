Repo-agent subagents: giving every repo agent what the arch has

          From start_subagent to the summary in the parent's chat

          Parent repo agent (its dock, Builder lane)
          calls start_subagent(goal, steps, maxIterations)
          a turn tagged subagent arrives: the summary
          Harness · RepoSubagentService + loop engine
          record created · goal loop armed on key repo~sub~id · parent tab + session remembered
          engine tick: parent's builder slot free? sibling writer idle? → send the WORK prompt (plan block + queued messages)
          NEEDS_HUMAN → loop escalates → record held, step blocked with the question
          answer from the dock lane or message_subagent → loop resumes
          LOOP_DONE → VERIFY prompt → GOAL_VERIFIED → done
          summary composed from the plan + last reply, queued for the parent
          parent slot free → one turn in the PARENT session, actor subagent
          Subagent (own CLI session, same checkout)
          works in the checkout · mark_step as it goes · its MCP URL carries &sub=id
